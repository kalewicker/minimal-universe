# R05a two-edge proposal and static audit

Date: 2026-10-24. Protocol: `R05a-v1`. Static audit: **pass**.
Scientific status: **untested new substrate**.

The [G2-path-v1 proposal](../docs/r05-two-edge.md) specifies a directed path LHS
`u→v, v→x` consuming two distinct edge occurrences. It defines all endpoint aliases,
ordered role assignments, loops and parallel edges, formal RHS ordering, atomic
consumption and output identity, up to two unique producer parents, match-based
scheduling, transactional resource stops, and checkpoint separation from G1.
It also lists the new controls and calibration needed before scientific use.

## Static evidence

The [registered matrix](../protocols/r05a.json) was checked with a direct
occurrence-pair matcher and a separate degree-count identity. The
[source-bound receipt](r05a.json) records:

| Check | Result |
| --- | ---: |
| Formal RHS multisets of lengths 0/1/2/3 | 1 / 16 / 136 / 816 |
| Total formal rules | 969 |
| Rules without / with a fresh vertex | 220 / 749 |
| Multigraph fixtures, 1–3 vertices and 0–4 edges | 790 |
| Ordered matches across those fixtures | 2,640 |
| Endpoint alias classes covered | 5 |
| Vertex-permutation comparisons | 4,435 |
| Occurrence-ID permutation comparisons | 13,989 |
| Explicit named fixtures, including an empty vertex set | 8 |
| Unordered match pairs with disjoint consumed sets | 797 |
| Unordered match pairs sharing one consumed occurrence | 3,802 |
| Unordered match pairs sharing both consumed occurrences | 562 |

Match counts agreed exactly with `sum indegree*outdegree - loop_count` on every
fixture. The permutation checks compared full ordered match sets, preserving
occurrence identity rather than deduplicating parallel arcs. Overlap counts are
descriptive totals over a finite fixture panel, not event probabilities or a
sample of future trajectories. The rule census is not an executed rule-by-seed
campaign and is not a correctness test of RHS execution.

An explicit empty-RHS counterexample leaves either a loop or a nonloop after
deleting one of two overlapping matches. Both residuals are terminal and retain
the same three vertices. Their different loop counts prove they are not
isomorphic. This disproves confluence for that rule. For two fixed disjoint
consumed sets, the proposal separately proves structural commutation up to
renaming fresh vertices and output IDs. It makes no general confluence claim.

All 38 Python tests passed. Seven new tests cover occurrence identity, self-loop
self-consumption rejection, scheduler weighting, isolates, sparse IDs, invalid
inputs, the terminal counterexample, and rejection of a changed registered rule
count. R04a prerequisite receipts and their pinned inputs/sources were verified.

## What remains untested

The deliverable includes a static matcher for the design audit, not a production
G2 transition runner. Atomic allocation, RHS materialization, two-parent event
records, RNG/replay/checkpoint behavior, and resource caps remain implementation
and independent verification work. No G2 production trajectories, candidate
statistics, target/sham interventions, or holdout jobs were executed.

The size identities change to `E(t)=E(0)+(k-2)*t` and `V(t)=V(0)+f*t`, conditional
on successful events. Eligibility may disappear even with multiple edges left.
Uniform-match exposure depends on the eligible path set; the old one-edge
untouched-edge survival formula cannot be reused. No emergence, adaptation,
learning, reproduction, or stronger causal organization claim follows from the
new matching capability or the counterexample.

## Reproduction and next milestone

The checker uses only the public source and compact receipts:

```sh
python3 -B scripts/audit_r05.py --verify reports/r05a.json
```

A new receipt requires an unused `--output` path. The checked-in receipt binds
the proposal, protocol, checker, tests, and prerequisite R04a receipt by SHA-256.
Bulk G1 evidence and the native binary are not required to verify this static
audit; its source-bound prerequisite chain checks the public receipts.

Next is R05b: register finite engineering budgets and fixtures, implement a G2
reference kernel, and independently validate its matching and replay. Later
measurement calibration and any campaign need their own registrations. All
16,774 reserved G1 jobs remain unopened.
